# kakarot v0.1.0

The first release of kakarot, a layered Go framework: **transport → middleware → endpoint → service → usecase → repository**, each layer with a typed contract. You write the domain types, the usecases and one annotated service interface; `kakarot gen` writes the endpoint and transport layers.

Requires **Go 1.27.4** or newer.

## Start a project

```console
$ go run github.com/gsoultan/kakarot/cmd/kakarot@v0.1.0 new example.com/acme/notes
$ cd notes
$ go get -tool github.com/gsoultan/kakarot/cmd/kakarot github.com/gsoultan/storm/cmd/storm
$ go generate ./...
$ go mod tidy
$ go test ./...            # passes with no database
$ go tool kakarot check    # layer rules, //kakarot: comments, generated code is current
```

## Modules

The core depends only on the Go standard library. Everything that needs a third-party library is its own module, so a project downloads only what it uses.

| Module | Install | Contents |
|---|---|---|
| core | `go get github.com/gsoultan/kakarot@v0.1.0` | endpoints, streams, middleware, errors, HTTP, auth, queue, test kit |
| data | `go get github.com/gsoultan/kakarot/data@v0.1.0` | storm transactions, outbox, idempotency |
| grpcx | `go get github.com/gsoultan/kakarot/transport/grpcx@v0.1.0` | gRPC services, clients, `.proto` and protobuf |
| wsx | `go get github.com/gsoultan/kakarot/transport/wsx@v0.1.0` | WebSocket streams |
| otelx | `go get github.com/gsoultan/kakarot/otelx@v0.1.0` | OpenTelemetry tracing and metrics |
| natsx | `go get github.com/gsoultan/kakarot/natsx@v0.1.0` | NATS JetStream broker |

## What is in it

### Core (`github.com/gsoultan/kakarot`)

- **Typed operations.** Every operation is a `kakarot.Endpoint[Req, Resp]` or a typed stream (`ServerStream`, `ClientStream`, `BidiStream`). No `any` and no casts in the public API.
- **Middleware.** Shared middleware never touches the request; middleware that needs it is a generic `TypedMiddleware[Req, Resp]`, checked by the compiler.
- **Errors as domain codes** (`E`, `Invalid`, `CodeOf`, `Is`, custom codes) that every transport maps once.
- **`App`** runs many servers with graceful shutdown. **`Job`** runs scheduled work. **`Page`** and typed cursors give keyset pagination.
- **`transport/httpx`**: router on `http.ServeMux`, typed `Handle`, request decoding from path, query, header and JSON body, SSE and NDJSON streams, uploads, OpenAPI 3.1.
- **`middleware`**: `Recover`, `Logging`, `Timeout`, `Validated`, `Retry`, `CircuitBreaker`, `RateLimit`, `LoadShed`, `Idempotent`.
- **`auth`**: typed principal in the context, `Bearer`, `Require`.
- **`queue`**: message consumers on typed topics, message headers, redelivery rules, dead letters, and an in-process broker.
- **`kakarottest`**: `Tx`, `Do`, `WantCode`, `WantField`, `Eventually`, `Serve`, `Publish`, `Clock`. Usecase and API tests need no database.

### data (`.../data`)

- `TxManager` on [storm](https://github.com/gsoultan/storm), with database errors mapped to domain codes.
- **Transactional outbox.** An event commits or rolls back with the rows it describes. The relay publishes at least once and claims rows with `FOR UPDATE SKIP LOCKED`, so several relays can run.
- `outbox.Carry` stores the headers of the call, such as a trace context, with each event.
- **Idempotency store**, scoped to the caller.

### grpcx (`.../transport/grpcx`)

- **Interface-first gRPC.** A service is built from typed endpoints with no `.proto` file and no protoc. The generated Go client is the same endpoints type as the server.
- **Protobuf clients.** `Service.Proto()` writes a `.proto` file from the service, and `grpcx.EnableProtobuf()` makes the server answer protobuf as well as JSON. One description of the Go types drives both, so the schema and the wire format cannot disagree.
- Go types map to messages, `optional`, `repeated`, `map`, `Timestamp`, `Duration`, **`enum`** (a string type with a `ProtoEnum` method) and **`oneof`** (pointer fields tagged `proto:",oneof=name"`).
- Bearer auth, custom status codes with error details, and `Carrier` for trace and context propagation.

### wsx (`.../transport/wsx`)

- Bidirectional streams over WebSocket, on the same typed stream contract as gRPC.

### otelx (`.../otelx`)

- One span and one duration metric per call on every transport, named by operation with the result code.
- A trace continues across HTTP, gRPC, queue messages and outbox events.

### Brokers: natsx, kafkax, sqsx

Each broker is both sides: the source of a `queue.Consumer` and the publisher of the outbox relay.

- **natsx**: NATS JetStream. Durable consumer groups, redelivery with backoff, deduplication by event ID.
- **kafkax**: Kafka. Offsets are committed after the handler returns. A failed message is retried in place, then sent to a dead-letter topic or skipped.
- **sqsx**: Amazon SQS. A handled message is deleted; a failed one becomes visible again after a backoff. FIFO queues group by key and deduplicate by event ID.

### cmd/kakarot

- **`new`** scaffolds a project with every layer, passing tests and an `AGENTS.md`.
- **`gen`** writes the endpoint and transport layers from a service interface marked with `//kakarot:service`, `//kakarot:http`, `//kakarot:grpc` and `//kakarot:queue`. A wrong comment is an error with the file, the line and the fix.
- **`check`** verifies what the compiler cannot: each layer imports only the layers below it, every `//kakarot:` comment is valid, and generated code is current.

### Examples

- `examples/orders`: a complete service on every layer and transport, with a committed `.proto` contract.
- `examples/wallet`: money transfers with auth, idempotency, a ledger, the outbox and gRPC.
- `examples/checkout`: a synchronous request followed by asynchronous payment, shipping, compensation and expiry.

## Upgrade note: outbox table

The `outbox_events` table has a `headers` column (JSON, default `{}`). A database created from an earlier commit of this repository needs a migration before the relay runs:

```console
$ storm diff add_outbox_headers
```

Projects that use storm's auto-migration pick the column up at start.

## Known limits

- **kafkax and sqsx are tested in memory only.** The Kafka tests run against an in-memory cluster and the SQS tests against an in-memory stand-in. Neither has been run against a production cluster or real AWS yet. Test against your own before relying on them.
- **Kafka retries hold back a partition.** Kafka cannot redeliver one record, so a failing message is retried in place until it succeeds or reaches `MaxDeliver`.
- **Protobuf field numbers follow struct field order.** Add fields at the end, or pin numbers with a `proto:"N"` tag. Keep the written `.proto` file under a test, as `examples/orders` does.
- **Protobuf JSON differs for enums.** HTTP and the Go client carry the string (`"paid"`); protobuf clients see the enum (`STATUS_PAID`).
- **`.proto` output is not part of `kakarot gen`.** The file comes from `Service.Proto()` at run time or in a test.
- **No brokers for RabbitMQ or Google Pub/Sub.** A broker is two small methods, and `natsx` is a template.
- **Dependency wiring is not generated.** `main.go` is hand-written by design.
- **Before v1.0.0 a minor version may change the API.** The changelog will say what to change.
